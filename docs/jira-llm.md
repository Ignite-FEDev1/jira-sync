# Jira 티켓 내용 생성기 (LLM 기반)

## 기능 개요
자유 형식 텍스트를 입력하면 H Chat API (Claude)를 활용하여 팀 컨벤션에 맞는 Jira 티켓 내용(wiki markup)을 자동 생성.

## 기술 스택
- API: H Chat API (`https://internal-apigw-kr.hmg-corp.io/hchat-in/api/v3/claude/messages`)
- 인증: Personal API Key (`H_CHAT_API_KEY`)
- 모델: `claude-sonnet-4-6` (기본값, `H_CHAT_API_MODEL`로 변경 가능)
- 허용 모델: `claude-sonnet-4-6`, `claude-sonnet-4-5`, `claude-haiku-4-5`

## 파일 구조
- `app/api/generate/ticket-content/route.ts` - API Route (H Chat 호출)
- `app/generate-ticket/page.tsx` - 프론트엔드 페이지
- `components/ui/textarea.tsx` - Textarea UI 컴포넌트

## 환경변수
```
H_CHAT_API_KEY=<Personal API Key>
H_CHAT_API_MODEL=claude-sonnet-4-6  # Optional
```

## 사용자 입력 필드
1. **업무 배경/히스토리** - 슬랙, 두레이 등에서 복사 붙여넣기한 맥락 정보
2. **업무 설명** - 사용자가 직접 작성하는 작업 내용 설명
3. **관련 URL** - 참고 링크 (기획서, 디자인, 관련 티켓 등)

## 티켓 형식과 작성 규칙
> TODO: 팀 컨벤션 문서 반영 예정

현재 확인된 필수 섹션:
- **작업 내용**: 이슈/해결 형식으로 작성. 사용자 관점에서 어떤 기능 개선/버그 수정인지 명확히 기재
- **사용자 전달 내용(공지)**: 사용자가 인지할 변화가 있는지, 공지 필요 여부
- **QA 시나리오**: 검증 절차를 단계별로 기재
- **작업배경**: 왜 이 작업이 필요한지
- **배포 후 영향도**: 배포 시 영향 범위

### 참고: 팀 내 공유 사항
- 배포대장 기준으로 운영팀이 사용자 공지를 작성하므로, 티켓 설명에 **사용자 관점**의 설명이 반드시 필요
- QA 시나리오만으로는 운영팀이 기능 내용 파악이 어려움
- 개발처리 티켓(FEHG→클론)에도 세부 설명 기재 필수

### 기존 티켓 예시

**예시 1: 버그 수정**
```
작업 내용
이슈: 사용자가 접속한지 1분 이상 경과한 게시글(이미지 포함)을 복사하여 붙여넣기 시, 이미지가 깨지는 현상
해결: 접속한지 1분 이상 경과한 게시글을 복사하더라도, 붙여넣기 시 이미지가 깨지지 않도록 수정

사용자 전달 내용(공지)
게시글 내 이미지 복사/붙여넣기 기능 개선(시간 소요시 붙여넣은 이미지가 깨지던 현상 조치)

[QA 시나리오]
브라우저 탭 두 개 띄우기 (A, B)
A탭은 이미지가 포함된 게시글 상세 진입
B탭은 게시글 작성 화면 진입
A탭에서 1분 이상(=signedUrl 만료 시간) 경과 후, 게시글 본문 드래그하여 복사
B탭에서 복사한 게시글 붙여넣기
붙여넣기 동작 시, 이미지 깨짐 현상 발생하지 않는지 확인
```

**예시 2: UX 개선**
```
작업 내용
게시글 답변하기 수정 팝업에서, 사용자가 추가로 수정한 내용이 없는데도 [수정하기] 버튼이 활성화 되는 현상 수정
팝업 연 후 실제로 수정한 내용이 있을 때에만 [수정하기] 버튼 활성화

사용자 전달 내용(공지)
불필요. (UX 개선으로, 사용성의 오류를 개선한 내용이 아니며, 유의미한 UX 개선이 아님. 개발 UX 표준 적용 처리)

[QA 시나리오]
<메인 기능>
게시글 상세 화면 진입
답변하기 수정 팝업 진입
수정한 내용이 없을 때, [수정] 버튼이 비활성화되는지 확인
수정한 내용이 있을 때, [수정] 버튼이 활성화되는지 확인
```
