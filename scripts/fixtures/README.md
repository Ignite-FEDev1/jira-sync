이 폴더에는 성격이 **정반대인** 골든 파일 둘이 있습니다. 다시 녹화해도 되는
것과, 다시 녹화하면 값어치가 사라지는 것입니다.

| 파일 | 무엇인가 | 다시 녹화 |
|---|---|---|
| `judge-cases.json` | 지금 Jira 상태의 판정 결과 | **해도 됩니다** — 판정을 일부러 바꿨을 때 |
| `alert-messages.json` | 알림 모델을 합치기 **전에** 나가던 글자 | **절대 안 됩니다** — 아래 참고 |

`.gitignore` 는 이 폴더의 `*.json` 을 통째로 무시하고
`alert-messages.json` 만 예외로 추적합니다(`.gitignore:79-82`). 둘의 성격이
다르기 때문이지, 실수가 아닙니다.

## `alert-messages.json` — 다시 걷으면 안 됩니다

14개 메시지는 **옮기기 전 글자**입니다. 알림 모델 통합
(`.superpowers/sdd/2026-09-30-alert-model-unification/`)의 유일한 합격 기준이
"채널에 나가는 글자가 한 자도 달라지지 않는다" 였고, 이 파일이 그 자를 들고
있습니다.

- 지금 코드로 다시 걷으면 **지금 코드가 정답이 됩니다** — 재는 대상과
  자가 같아져 측정 자체가 사라집니다
- 대조는 `--verify` 로만 합니다. 이 모드는 파일을 안 건드립니다

```bash
# 버리는 로컬 Postgres 에 마이그레이션을 전부 올린 뒤
npx tsx scripts/record-alert-messages.mts "<버리는 DB 주소>" --verify
```

신선한 DB 에 마이그레이션을 재생하는 요령은
`supabase/migrations/README.md` 의 "신선한 DB 에 처음부터 재생할 때" 에 있습니다.

**덮어 쓰게 되는 경우는 하나뿐입니다** — 측정이 빠진 갈래를 *더할* 때입니다
(실제로 10개 → 14개로 두 번 늘렸습니다). 그때도 먼저 있던 키의 글자는
한 자도 안 바뀌어야 하고, 바뀌었다면 그것이 바로 회귀입니다.

**인자 없이 실행하면 파일을 다시 씁니다.** `--verify` 를 붙이세요.

## `judge-cases.json` — 판정 회귀 픽스처

`judge-cases.json` 은 **실제 Jira 응답을 녹화한 것**입니다.

## 무엇에 쓰나

판정 로직을 고칠 때 답이 달라졌는지 봅니다.

- 판정이 틀려도 **오류가 안 납니다** — 틀린 사람에게 알림이 갈 뿐입니다
- 그래서 테스트 말고는 알 방법이 없습니다
- `via` · `classification` · `name` · `reason` 네 가지를 고정합니다
- `reason` 까지 고정하는 이유: 그 문장이 그대로 Slack 에 나갑니다

## 다시 녹화하기

```bash
set -a && . ./.env.local && set +a
npx tsx scripts/qa-router.record.mts
```

필요한 것: `IGNITE_JIRA_EMAIL`, `IGNITE_JIRA_API_TOKEN`
바꿀 수 있는 것: `QA_ROUTER_FILTER_ID` (기본 12571)

**언제 다시 녹화하나**

- 판정을 **일부러** 바꿨을 때. 이때는 diff 를 눈으로 확인하고 녹화합니다
- 표본을 넓히고 싶을 때 (`SAMPLE` 상수)

**언제 녹화하면 안 되나**

- 테스트가 깨졌는데 이유를 모를 때. 녹화는 그 변화를 **정답으로 만들어
  버립니다** — 회귀를 지우는 것과 같습니다

## 지금 표본의 한계

| 단계 | 건수 |
|---|---|
| `none` (판정 불가) | 22 |
| `assigned` | 14 |
| `epic` | 3 |
| `siblings` | **1** |
| `ref_owner` | **0** |

`ref_owner` 가 0건인 것은 **의도한 것**입니다. 백테스트에서 3/29(10%)로 나와
기본 순서에서 뺐습니다(`JUDGE_TIERS`). 녹화는 기본 순서로 돌므로 그 단계는
구조적으로 표본에 안 나옵니다.

`siblings` 는 1건뿐이라 **회귀 테스트가 그 단계를 거의 못 지킵니다.**
그 단계를 고칠 때는 백테스트(`scripts/qa-router-backtest.mts`)로 따로
확인해야 합니다.

`none` 이 22건인 것은 나쁜 신호가 아닙니다. 녹화는 **지금** Jira 상태로
돌기 때문에, 트리아지가 이미 넘긴 티켓은 레이블·형제가 정리돼 판정이
안 붙는 경우가 많습니다. 판정 시점 상태로 되감아 재는 것은 백테스트의
일이고, 이 픽스처는 **"코드를 고쳐도 같은 답이 나오나"** 만 지킵니다.

## 왜 이렇게 작나 (909KB)

녹화할 때 판정이 안 읽는 필드를 덜어냅니다 — `self` `expand` `avatarUrls`
`emailAddress` 등. 그대로 두면 2.3MB 였고, 그 크기에서는 사람이 diff 를
읽을 수 없습니다. 골든 파일은 읽을 수 있어야 값어치가 있습니다.
